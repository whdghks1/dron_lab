# DRONE LAB — Seoul Flight v0.13

설치 없이 브라우저에서 서울의 실제 공간 관계를 따라 비행하는 웹 기반 드론 여행 시뮬레이터입니다. **홍제천 인공폭포 일대**와 **청계광장–수표교 청계천 도심 구간**을 지역 선택기에서 전환할 수 있습니다.

기존 Canvas 2D 프로토타입은 `dist/`에 그대로 보존되어 있습니다. 현재 MVP는 Vite + TypeScript + Three.js 기반의 새 구조로 실행됩니다.

## 현재 구현 범위

- OpenStreetMap 스냅샷에 기반한 홍제천 수면, 자전거길·산책로, 도로, 교량과 338개 건물 동 위치
- 청계천 도심 1,029개 건물, 283개 도로, 198개 보행 경로와 실제 교량 형상
- 청계광장·모전교·광통교·광교·삼일교·수표교를 잇는 두 번째 탐험 코스

- 실제 위·경도를 기준점 중심의 로컬 미터 좌표로 변환
- 보조 조종 자유 비행: 입력 해제 시 자동 감속, 무입력 시 고도 유지

## 설치 및 실행

Node.js 20 이상을 권장합니다.

```bash
npm install
npm run dev
```

터미널에 표시된 주소(기본 `http://127.0.0.1:5173`)를 엽니다.

프로덕션 빌드와 미리보기:

```bash
npm run build
npm run preview
```

핵심 계산 테스트:

```bash
npm test
npm run perf:scene
```

## 조작

- `W A S D`: 전후좌우 이동
- `↑ ↓`: 상승·하강
- `Q E` 또는 `← →`: 회전
- `Space`: 브레이크
- `Shift`: 부스트
- `C`: 추적/1인칭 시점 전환
- `P`: 일시정지/재개
- `R`: 출발점 초기화
- `L`: 기록된 비행 경로 재생/중지

안전 착륙은 출발 패드 반경 5.2 m 안에서 수평 속도 2.5 m/s 이하로 줄인 뒤 `↓`를 눌러 지상 1.3 m까지 내려오면 판정됩니다. 탐험 코스 기록은 모든 지점을 통과하고 출발 패드에 착륙했을 때 저장됩니다.

탭이 비활성화되거나 창이 포커스를 잃으면 눌린 입력 상태를 즉시 지웁니다. 모바일에서는 화면 하단의 이동·고도 버튼을 사용합니다.

## 프로젝트 구조

```text
src/
  app/DroneLabApp.ts             앱 수명주기와 게임 루프
  game/                          입력, 비행 물리, 카메라, 충돌
  world/                         Three.js 장면, 표고, 청크와 LOD
    details/                     교량·제방·소품·식생·파사드·랜드마크 빌더
  areas/
    types.ts                     지역 데이터 공통 인터페이스
    registry.ts                  지역 목록, 동적 로더와 URL 지역 선택
    hongjecheon/
      config.ts                  기준 좌표, 경계, 출발점, 코스
      details.ts                 홍제천 전용 교량·제방·식생 설정
      prop-rules.ts              실제 경로 ID 기반 제작 소품 규칙
      landmarks.ts               제작 랜드마크와 충돌 설정
      data/                      OSM·DEM 정적 스냅샷과 로더
    cheonggyecheon/              청계천 config, OSM·DEM, 32개 동적 청크
    JsonChunkSource.ts           지역 공통 JSON 청크 로더
  ui/                            HUD, 미니맵, 미션 패널
  utils/                         좌표 변환과 순수 계산 함수
public/textures/buildings/       권리가 확인된 건물 외벽 사진
public/textures/materials/       출처가 기록된 웹 최적화 PBR 재질
scripts/import-osm.mjs           Overpass 결과를 지역 스냅샷으로 변환
scripts/import-dem.mjs           SRTM HGT를 작은 표고 격자로 변환
scripts/build-area-chunks.mjs    OSM 스냅샷을 240 m 런타임 청크로 분할
dist/                            보존된 Canvas 2D 초기 프로토타입
```

지역 데이터, 비행 계산, 장면 구성, UI를 분리해 다른 서울 지역을 같은 인터페이스로 추가할 수 있습니다. 새 로더를 `src/areas/registry.ts`에 등록하면 상단 지역 선택기와 `?area=<id>` URL에서 자동으로 사용할 수 있습니다. 현재 `hongjecheon-waterfall`, `cheonggyecheon-downtown` 두 지역이 등록되어 선택기와 URL로 전환됩니다.

건물, 도로, 길, 교량과 공원은 240 m JSON 셀로 분리됩니다. 홍제천은 30개, 청계천은 32개 청크이며 시작할 때 드론 주변 파일만 동적으로 가져옵니다. 이동 중 새 반경에 들어온 셀을 추가로 로드하고 저·중·고 품질의 로딩 반경은 약 200/320/440 m입니다. 건물은 가까이에서 외벽·지붕 디테일을 표시하고 멀리서는 같은 실제 평면 윤곽을 유지한 단순 돌출 형상으로 전환됩니다. 나무는 줄기·수관에서 저폴리곤 수관으로 전환되며 품질 변경 시 반경과 LOD 거리도 즉시 갱신됩니다.

v0.12부터 건물 충돌도 직사각형 경계 상자가 아니라 OSM 평면 외곽선을 사용합니다. 오목하거나 회전된 건물의 빈 경계 상자 모서리에서 발생하던 조기 충돌을 없애되, 드론 반경만큼 외벽에서 안전 거리를 유지합니다. 도로는 코드 생성 아스팔트 질감과 도로 등급별 폭을 사용하고 Medium/High에서 보도·가장자리 선·중앙 점선을 추가합니다. 다음 OSM 갱신 데이터에 `width`, `lanes`, `sidewalk`, `surface`가 있으면 변환기가 보존하며 렌더러는 폭·차선·보도 정보를 추정 기본값보다 우선합니다.

외벽은 작은 창문·패널 패턴을 런타임에 생성해 실제 건물 윤곽에 반복 매핑합니다. 중·고품질에서는 실제 윤곽의 옥상 둘레에 파라펫을 만들고, 건물 크기와 ID를 기준으로 기계실·물탱크·캐노피를 결정적으로 배치합니다. 공동주택과 상업·의료 건물에는 긴 외벽을 따라 층별 발코니 띠를 추가하며 저층 주택은 지붕 볼륨을 분리합니다. 하천도 외부 이미지 없이 두 방향의 물결과 미세 하이라이트를 만든 뒤 텍스처 좌표를 천천히 이동해 흐름을 표현합니다.

### 홍제천 근거리 디테일

홍제천 교량은 일반 도로 리본과 분리해 상판, 구조 두께, 교각, 교대, 난간, 하부 그림자와 충돌 영역을 생성합니다. OSM 중심선은 실제 데이터지만 폭·높이·교각 수는 `details.ts`의 `estimated` override이며, `modelUrl` 필드를 통해 향후 권리가 확인된 GLB로 교체할 수 있습니다.

제방은 하천 중심선을 따라 구간별로 `concrete-slope`, `vertical-wall`, `stone-bank`, `grass-slope`, `walkway-edge` 프로파일을 사용합니다. 난간·가로등·벤치 등 반복 소품과 3종 식생은 `InstancedMesh`로 묶고 품질별 밀도와 가시성을 조절합니다. 제방 프로파일, 계단, 소품과 식생은 현장 실측이 아닌 `authored` 제작 데이터입니다.

v0.13은 홍제폭포를 단순 상자형 placeholder에서 불규칙 암벽과 여러 낙수 줄기, 폭포지, 물보라, 관람 데크, 곡선 보행로, 징검석과 내부순환로 교각을 가진 제작 모델로 교체했습니다. 공식 서울 관광 안내의 약 60 m 폭·25 m 높이는 외형 기준으로 사용했고, OSM 하천·경로의 상대 위치와 공개 현장 사진을 대조해 암벽이 하천 서쪽을 향하도록 배치했습니다. 깊이, 세부 암반, 데크와 수로 고도는 실측값이 아닌 제작값입니다. 세부 근거와 검수 기준은 [v0.13 홍제천 시각 보정 기록](docs/hongjecheon-visual-calibration-v0.13.md)에 정리했습니다.

SRTM은 좁은 하천보다 격자가 커서 동쪽 산지 표고가 수로 안으로 번지는 구간이 있습니다. v0.13은 홍제폭포 주변 하천 중심선에 완만한 하류 경사를 지정하고, 중심 9.2 m 밖에서 8.2 m에 걸쳐 원본 DEM으로 되돌아가도록 혼합합니다. 원본 표고는 `sampleBaseHeight()`로 그대로 보존되며 홍제천 전용 설정이 없는 다른 지역에는 적용되지 않습니다.

v0.11부터 콘크리트와 석재 제방에는 Poly Haven의 CC0 PBR 재질을 적용합니다. 모든 품질에서 1K diffuse를 사용하고, Medium/High에서만 512px OpenGL normal과 roughness를 추가합니다. 네트워크 로드에 실패하면 기존 코드 생성 재질을 유지하며, High/Medium에서 Low로 전환하면 추가 표면 맵을 해제하고 GPU 리소스를 정리합니다.

### 실제 건물 사진 사용

실제 사진도 사용할 수 있습니다. v0.10은 Wikimedia Commons에서 저자와 CC BY-SA 4.0을 확인한 서대문구청 외관 사진을 OSM building way `174111567`의 서측 외벽에만 적용합니다. 촬영 GPS와 동쪽을 향한 촬영 방향을 근거로 사진이 바라본 외벽을 서측으로 판정했으며 나머지 면은 절차형 재질을 유지합니다. 앱 하단 저자·라이선스 링크와 같은 폴더의 `LICENSE.md`에서 원문과 변경 방식을 확인할 수 있습니다. 추가 사진은 `facades`에 `north/east/south/west` 방향과 `url`, 반복·오프셋 값을 등록하고, 기존 `sideUrls` 형식도 계속 지원합니다.

촬영 방향이 다른 한 장의 사진을 건물 전체 면에 반복하면 실제성과 왜곡이 섞일 수 있습니다. 품질을 높이려면 정면 보정한 면별 사진이 필요합니다. Google Street View 같은 지도 서비스 이미지는 이용 약관과 저작권을 확인하지 않은 채 내려받거나 잘라 텍스처로 포함하면 안 됩니다.

### 비행 기록과 안전 정보

비행 중 위치와 자세를 약 0.25초 간격으로 기록하며 장면에 경로선을 표시합니다. 미션 패널의 **경로 재생** 또는 `L`로 현재 기록을 처음부터 재생할 수 있고, 출발점 초기화 시 기록도 지워집니다. 기록은 브라우저 메모리에만 있으며 파일이나 서버로 전송하지 않습니다.

상단 **비행 안전** 패널은 공역 데이터의 연결 상태와 출처를 표시하기 위한 구조입니다. 현재 두 지역 모두 `unavailable`로 등록되어 공식 공역이나 임시 비행 제한을 표시하지 않습니다. 앱의 100 m 제한과 지도 경계는 게임 규칙일 뿐 실제 비행 가능 여부가 아닙니다. 데이터 계약과 연결 원칙은 [공역 데이터 문서](docs/airspace.md)를 참고하세요.

## 지역 데이터 구조와 새 지역 추가

`AreaSnapshot`은 `buildings`, `roads`, `paths`, `water`, `bridges`, `parks` 배열로 구성됩니다. 각 형상은 원본 위·경도를 유지하며, 렌더링할 때 `geoToLocal()`로 기준점 중심 미터 좌표에 투영합니다. 동쪽은 `+X`, 북쪽은 `-Z`, 고도는 `+Y`입니다. 건물은 일반 OSM way뿐 아니라 건물 multipolygon relation의 닫힌 `outer` member도 각각의 실제 way ID로 가져옵니다.

`ElevationGrid`는 41×33 표고 격자와 기준점 표고를 보관합니다. 런타임은 이 격자를 이중선형 보간하고 기준점 표고를 빼서 Three.js 상대고도로 사용합니다. HUD 고도와 1.1–100 m 비행 제한은 현재 지면을 기준으로 계산됩니다.

새 지역을 추가하려면:

1. `src/areas/<area>/config.ts`에 기준 위·경도, 비행 경계, 출발점, 코스를 정의합니다.
2. 같은 `AreaSnapshot` 인터페이스의 정적 데이터와 로더를 추가합니다.
3. `World`에 지역 고유 장면 빌더가 필요하면 공통 지형 빌더와 분리합니다.
4. 앱 시작 시 선택된 지역의 config와 loader를 주입하도록 지역 선택 UI를 연결합니다.

OSM 스냅샷을 갱신할 때는 Overpass JSON을 받은 뒤 지역 ID와 함께 변환기를 사용합니다.

```bash
node scripts/import-osm.mjs /path/to/overpass-result.json hongjecheon
node scripts/import-dem.mjs /path/to/N37E126.hgt.gz hongjecheon
npm run data:chunks

node scripts/import-osm.mjs /path/to/overpass-result.json cheonggyecheon
node scripts/import-dem.mjs /path/to/N37E126.hgt.gz cheonggyecheon
npm run data:chunks:cheonggyecheon
```

사용한 쿼리 범위와 데이터 구분은 [데이터 출처 문서](docs/data-sources.md)를 참고하세요.

## 알려진 한계

- SRTM 원본 해상도가 약 30 m이므로 하천 제방, 계단, 작은 구조물의 미세 고저는 표현되지 않습니다. 홍제폭포 주변 수로만 제작 보정선을 사용하며 측량 표고가 아닙니다.
- OSM에 높이가 없는 건물은 식별자 기반의 결정적 추정 높이를 사용하며, 상세 설비 위치 역시 실제 설비 조사가 아닌 절차적 표현입니다.
- 현재 포함된 OSM 스냅샷에는 도로 폭·차선·보도 태그가 충분하지 않아 도로 등급별 기본 폭과 보도·차선 규칙을 사용합니다.
- 나무, 착륙 패드, 탐험 링은 비행 경험을 위한 절차적/제작 요소이며 실제 개체 위치가 아닙니다.
- 교량 충돌은 아직 건물 수준의 정밀 충돌이 아니며, 실제 드론 비행 규제·공역 데이터는 연결되어 있지 않습니다.
- 동적 import 모듈 자체는 브라우저 캐시에 남지만, 비활성 청크가 품질별 상한을 넘으면 LRU 순서로 장면 geometry와 충돌 데이터를 제거합니다.
- 절차형 건물 텍스처는 용도·연식·재질을 구분하지 않는 공통 스타일이며, 수면은 실제 유속이나 날씨를 반영하지 않습니다.
- 실제 사진은 서대문구청 서측 외벽 한 곳에만 적용되며 사진 촬영 시점과 현재 외관이 다를 수 있습니다.
- 청계천 도심 SRTM은 건물 표면의 영향을 받을 수 있어 세밀한 지면 높이는 실제 측량값과 다를 수 있습니다.
- 홍제천 제방 단면·계단·교량 세부 높이·소품·식생·홍제폭포 세부 암반과 시설물 형상은 실제 위치/OSM 경로와 공개 사진을 참고한 제작 또는 추정 모델입니다.
- CC0 PBR 재질은 실제 홍제천 표면을 촬영한 자료가 아니라 재질의 질감 표현을 개선하기 위한 범용 텍스처입니다.

## 다음 개발 단계

다음 우선순위는 동일한 시점·화각으로 촬영한 사용자 현장 사진 또는 배포 화면 캡처를 나란히 비교해 폭포 암반 윤곽, 데크와 교각 위치를 2차 보정하는 것입니다. 그다음 `width`·`lanes`·`sidewalk` 태그가 풍부한 최신 도로 스냅샷, 교량별 실측 치수·GLB 모델, 공통 GLB 캐시·해제 파이프라인과 공식 공역 데이터 갱신 정책을 확정해야 합니다. 배포와 장시간 비행 점검 방법은 [배포 문서](docs/deployment.md)를 참고하세요.
